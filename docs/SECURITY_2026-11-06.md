# Security and robustness pass, 2026-11-06

## Fixed in this repo
- **Signed updates (OTA).** Every file in `latest.json` now carries an Ed25519 signature (`sig`) over
  `esb-ota-v1\n<version>\n<file>\n<sha256>`. The app refuses an unsigned or wrongly signed release (`src/platform/ota.ts`,
  `OTA_PUBLIC_KEY`). `tools/release.mjs` signs with the private key at `~/.esb-ota/ed25519-private.pem` (or `$ESB_OTA_KEY`).
  **Back that file up.** It is not in the repo or on Cloudflare. If it is lost, phones running this build accept no
  further OTA update until a new APK with a new public key is installed.
- **Content-Security-Policy** on release builds (`vite.config.ts`): no inline or remote script, no `<object>`, no `<base>`.
  Network, images and frames stay open (many hosts). Dev builds have no CSP (Vite's refresh preamble is inline).
- `openExternal` opens only `http(s)` links (never `javascript:`, `intent:`, `file:`).
- ShareTarget ignores `content://` URIs from this app's own provider (a hostile app could otherwise make the app
  "share" one of its own private cache files back in).
- `tools/apk-phone.sh` unsets `CAP_LIVE` and stops if the synced config holds a dev URL or WebView debugging.

## Known, left as is
- Release APKs are signed with the Android debug keystore. Changing the key now would force an uninstall (every login
  and story on the phone lost). Move to a real release key only together with a planned reinstall.
- `res/xml/file_paths.xml` shares broad paths (`external-path "."`). The Camera plugin relies on them; narrow only with a
  camera test on the phone.
